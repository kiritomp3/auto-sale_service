# Модели генерации

Анализ фотографий, тексты карточек, тексты для примерки и AI-чат Ozon используют
**Google Gemini 3.8 Flash через Kie.ai**. Прямых запросов к Claude в рабочем
контейнере больше нет. Старый клиент Claude сохранён для совместимости, но не
подключён к сервисам.

Это смена поставщика модели с Anthropic на Google, а не полный уход от шлюза
Kie.ai. Генерация изображений по-прежнему использует GPT Image 2 через Kie.ai.

## Настройка

Требуется существующая переменная `KIE_AI_API_KEY`. Ключи `GEMINI_API_KEY` и
`OPENAI_API_KEY` для этого маршрута не используются. Секреты задавайте в окружении
сервера; не добавляйте их в коммиты.

После обновления кода сервис необходимо пересобрать и перезапустить:

```sh
docker compose up -d --build wb-cards-api
```

## Формат запросов

- Текст: `https://api.kie.ai/gemini-3-8-flash-openai/v1/chat/completions`,
  `model=gemini-3-8-flash`.
- Авторизация: `Authorization: Bearer …`.
- Фото сначала загружается в файловое хранилище Kie.ai, затем передаётся как
  HTTP(S)-ссылка в блоке `image_url`. Большие встроенные data URL шлюз отклоняет.
- Ответ читается из `choices[0].message.content`; пустые, обрезанные ответы и
  ошибки внутри HTTP 200 не считаются успешной генерацией.
- При временных HTTP-ошибках и временных ошибках внутри HTTP 200 выполняется
  до четырёх попыток с паузами. Ошибки авторизации, баланса и валидации запроса
  не повторяются автоматически.
- Если ни одно изображение не создано, задача завершается с `status=failed`.
  Исходное фото больше не подменяет сгенерированный результат.
- При частичном успехе `cards` содержит только готовые изображения в исходном
  порядке. `image_generation_errors` сохраняется в ответе и в Redis; описание
  может отдельно содержать `metadata_error`.
- Публичные ошибки содержат безопасную причину; signed URL, исходные ответы
  провайдера и содержимое запросов в них не копируются. В логах остаются
  `reason` и `provider_code`.

Документация: [Gemini 3.8 Flash в Kie.ai](https://docs.kie.ai/market/gemini/gemini-3-8-flash-openai).

## Проверки

```sh
python -m unittest discover -s tests -v
```

Для проверки реальной генерации создайте задачу через `POST /cards` с
`n_cards=1` и дождитесь `done` по `GET /crads/{job_id}`. Такая проверка обращается
к внешнему API и расходует кредиты. Одного успешного ответа на текстовый запрос
недостаточно для проверки всей джобы.

12 ноября 2026 года выполнена проверка нового кода в изолированном процессе
с безопасным фото из репозитория: vision → GPT Image 2 → описание, одна карточка.
Результат: `done`, PNG 1024×1536, без `image_generation_errors` и `metadata_error`.
Рабочие модели не менялись. Минимальный диагностический запрос также зафиксировал
перемежающуюся ошибку Kie.ai `code=503` внутри HTTP 200; повтор прошёл.
Историческая ошибка `code=400` сама по себе не доказывает снятие модели с поддержки.
